# Design Changes

Changes to the portfolio website requested through a design image and approved requirements.

## Language

**Design image**:
The visual reference for a requested website change. It supplies layout and appearance details within the approved scope; explicit approved requirements take precedence when they conflict.

**Approved requirements**:
The requirements and clarification answers accepted by the artist as the scope of a website change.

**Implementation**:
The work of changing the website using the design image and approved requirements. It includes inspecting the existing code and planning the changes, without a separate technical instructions stage.

**Design verification**:
Assessment of the changed website against the design image and approved requirements, including rendered pages, automated checks, and code review.

**Completed design change**:
A design change with a pull request that has passed required checks and design verification. Completion does not mean the change has been merged or deployed.

**No changes needed**:
A successful outcome where verification establishes that the existing website already satisfies the approved requirements and design image. It does not require a new pull request.

**Design update budget**:
The configured monetary allowance for one requested UI update, covering design analysis, clarification, **Implementation**, **Design verification**, repairs, and retries through handoff for human review. The artist does not choose this allowance for each update.

**Budget stop**:
A halt to automated work when the **Design update budget** is exhausted or its remaining allowance cannot be established. Partial work is preserved and the artist is directed to contact the developer.
