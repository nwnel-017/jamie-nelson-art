# Design update budget: feasibility research

Investigated 2026-11-28. Research only; no runtime changes or paid calls. **Fact** means inspected source/documentation; **proposal/inference** means a design conclusion; **untested** means no execution evidence.

## Current implementation direction

The latest specification in GitHub issue #42 supersedes the candidate topology below where they differ: one shared budget function, direct backend calls, a thin external-worker endpoint, one durable budget record per update, and at most one active request. The spike remains historical evidence; its per-request SQLite rows are not the production schema.

## Settled scope

- `AI_DESIGN_BUDGET_USD` configures one monetary allowance per requested UI update. No configuration snapshot handling.
- The allowance includes initial design analysis, clarifications, implementation, verification, repairs and retries through handoff for human review. Reserve the maximum cost **before each upstream request**, then settle actual usage; do not estimate an entire task upfront.
- Unknown usage retains the full reservation and stops further work. A Budget stop preserves partial work and tells the artist to contact the developer. These are accepted requirements, consistent with [GLOSSARY.md](../GLOSSARY.md); this note does not change [ADR-0001](adr/0001-image-driven-implementation.md).

## Verdict

- **Custom endpoint alone does not suffice.** It redirects the action's permitted Responses traffic; it neither accounts for spending nor covers the app's separate Chat Completions calls, forbids all alternative billable tools, or supplies durable job identity.
- **Conditionally feasible:** a small shared gateway plus an atomic ledger in the existing database, with exact runtime pins, only bounded requests, and exclusive custody of provider credentials. HTTP-only is the smallest candidate topology.
- **A strict provider-invoice ceiling is not established.** Routing, input-count compatibility, accounting after failures, and provider guarantees about internal retries still need validation. A mock can prove admission/routing behavior, never OpenAI billing behavior. Do not ship or describe this as a proven hard cap yet.

- **Fact:** HTTP requests use `/responses`; WebSocket connections use the Responses path through the selected provider and can fall back to HTTP. WebSockets require provider capability; the action-generated provider omits it, whose default is false. Thus this inspected action configuration selects HTTP. [HTTP endpoint](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/codex-api/src/endpoint/responses.rs), [client transport](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/client.rs#L1331-L1345), [capability defaults](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/model-provider-info/src/lib.rs#L223-L231).
- **Fact:** normal compaction uses a model client session; foreground v2 compaction uses `stream`, background v2 uses `ResponsesHttpExecutor`. These inspected paths issue Responses inference, rather than a separate `/responses/compact` request. [Compaction](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/compact.rs#L294-L343), [v2 compaction](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/compact_remote_v2.rs#L300-L352). The public API separately supports [server-side and standalone compaction](https://developers.openai.com/api/docs/guides/compaction.md); the stock proxy would reject a standalone compact path. **Proposal:** reject that endpoint and `context_management` until independently bounded; do not silently forward them.
- **Fact:** request retries default to 4, stream retries to 5; provider transport enables 5xx and transport retries. Turn and compaction loops have additional retry handling. Each newly forwarded inference attempt therefore needs a reservation. [Provider retry configuration](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/model-provider-info/src/lib.rs#L493-L507), [defaults](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/model-provider-info/src/lib.rs#L74-L82), [turn loop](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/session/turn.rs#L1921-L1945). Retry limits alone are not monetary limits.
- **Fact:** subagents inherit effective configuration/provider, with role configuration layered on top and optional model overrides. This supports routing inheritance, not proof that every child configuration is safe. [Handler](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/tools/handlers/multi_agents.rs#L1-L6), [spawn](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs#L98-L118). **Proposal:** disable subagents initially; if required, constrain roles and enforce the same gateway/model allowlist for children.
- **Fact:** Codex serializes the resolved model and service tier, but its normal `ResponsesApiRequest` has no `max_output_tokens` field. [Request struct](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/codex-api/src/common.rs#L286-L314), [construction](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/client.rs#L1278-L1316). **Proposal:** gateway injects a bounded output maximum; no prompt instruction substitutes for it. Model changes must be re-priced or rejected at every request.
- **Fact:** initial analysis/clarifications use a separate provider-neutral fetch client posting `/chat/completions`, with `max_completion_tokens: 8192`, a 45-second timeout, and no usage accounting. [Client](../server/utils/agent/chat-completion-model.ts), [factory](../server/utils/agent/model-factory.ts), [initial analysis](../server/services/gather-requirements.service.ts), [clarification](../server/services/clarify-requirements.service.ts). **Proposal:** route these through the same ledger. Smallest uniform accounting surface is a deliberate Responses migration; retaining Chat requires a separately proven counting adapter. Responses counting does not establish identical Chat tokenization.

## Bounding one request

- **Documented:** `POST /v1/responses/input_tokens` counts text, images, files, tools, conversations and structural formatting; OpenAI calls this the exact input count. Local text tokenizers are insufficient for multimodal/tool payloads. [Counting guide](https://developers.openai.com/api/docs/guides/token-counting.md), [endpoint schema](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count). **Untested:** actual Codex histories, encrypted compaction, custom tool schemas and model compatibility. Count the exact normalized request; use immutable image bytes, not mutable remote URLs. Reject opaque state references unless the counter resolves the same complete context.
- **Unresolved:** neither the inspected counting guide nor pricing page explicitly states a price/free guarantee for counting. Do not assume zero cost. Confirm before using it to enforce a strict allowance; otherwise the preflight itself lacks a proved cost bound. A conservative per-request context-window bound is a possible fallback only after proving the selected model's accepted input/output maxima; it wastes allowance but is not an estimate of the whole task.
- **Documented:** Responses `max_output_tokens` bounds generated output including reasoning. Reasoning is charged as output, even if nothing visible is returned; an incomplete response may still cost money. [Output cap](https://developers.openai.com/api/reference/resources/responses/methods/create.md), [reasoning costs](https://developers.openai.com/api/docs/guides/reasoning). Do not add reasoning usage to total output again.
- **Documented:** the API defaults to service tier `auto`; `default` requests standard processing, and the returned tier can differ. [Tier contract](https://developers.openai.com/api/reference/resources/responses/methods/create.md). **Proposal:** force `default`, permit only reviewed model IDs, reject unknown pricing, and stop on unexpected served model/tier. Detecting a mismatch after charging cannot repair an insufficient reservation; its worst-case price needs a bound first.
- **Documented prices at investigation time:** GPT-5.4 standard short-context input/output are $2.50/$15 per million tokens; long-context are $5/$22.50. Cached input has separate rates. Web search has call fees plus content-token costs; containers and file search have separate fees. [Pricing](https://developers.openai.com/api/docs/pricing.md). **Proposal:** reserve uncached input at the highest applicable context rate plus the enforced output maximum at its highest applicable rate; settle using actual categories. Deny explicit cache-write options unless their surcharge is included. Never assume a cache hit or short-context rate.
- **Proposal:** allow only local function/custom tools needed for code and browser work. Reject hosted search, image generation, file search, hosted containers, paid MCP services, audio, uploads and unknown tool types/endpoints. Output caps do not bound tool fees or extra retrieved input. The gateway cannot control an external paid API invoked by shell/MCP; credential and egress isolation must also prevent that bypass.
- **Unresolved:** inspected official sources do not establish a universal charge bound for server-internal retries, failures, or inference continuing after disconnection. Do not assume timeout/cancellation/5xx means free, or that an idempotency key prevents duplicate inference. A client retry is a new reservation; after an ambiguous upstream result, retain the reservation and deny subsequent requests. This bounds admitted requests **only if** each provider request really has the assumed maximum charge.

## Smallest candidate topology (proposal, not implemented)

1. Use one trusted gateway and the existing database, not a new billing platform. Both app analysis and CI call it; only it holds the OpenAI key. Pin CLI **and proxy** versions. Keep HTTP only and disable optional agents/hosted tools initially.
2. Bind credentials to the canonical design update before initial analysis. For CI, verify GitHub OIDC repository, workflow identity, run/attempt and claimed update relationship server-side; issue a short-lived gateway token bound to that update and phase. Repairs/review/reruns resolve to the same update. Never trust a caller-supplied update header/path without this binding. Separate gateway tokens from provider credentials.
3. Read `AI_DESIGN_BUDGET_USD` as valid positive decimal money; fail closed if absent/invalid or remaining allowance is uncertain. Maintain cumulative spend/reservations across phases; never reset the allowance on a workflow retry. No config snapshot subsystem.
4. Authenticate, strictly validate method/path/body/model/tier/tools, inject the output cap, establish the maximum charge, then atomically reserve it against the update. Use integer monetary units with conservative rounding. In one transaction/row lock enforce `spent + held + new_reservation <= allowance`. Crash-safe request IDs and states prevent double settlement. Counter/DB failure means no inference forwarding.
5. Persist reservation **before** forwarding. Forward exactly once without automatic upstream retries or redirects. Parse usage independently of client receipt. Atomically replace the reservation with actual charge only after authoritative final usage; a failure/incomplete response with valid usage still costs money. Duplicate events settle once. If usage is missing, inconsistent, exceeds the bound, or the gateway crashes after sending, keep the hold and mark the update stopped; holds must not expire into available funds.
6. Deny later calls for stopped updates, including concurrent agents, retries and other phases. Already admitted concurrent requests remain covered by their reservations; sequential requests are simplest. Preserve existing partial artifacts/patches and surface: “Work stopped because the design update budget could not cover the next request or its remaining allowance could not be confirmed. Your partial work has been kept. Contact the developer.”
7. Deny network bypass, not just config overrides: no provider keys/login sessions in agent environments; no alternate provider/API routes or paid tool credentials; constrain egress to trusted wrappers/gateway. Endpoint configuration alone cannot establish this boundary. Reuse existing isolation where possible; runner-wide enforcement is **unproven**, so treat it as a blocker rather than assuming `drop-sudo` supplies it.

## Local mock spike plan

This was the initial research plan. The executed subset and limitations are recorded below. Use a temporary directory and loopback mock upstream with fake credentials; no production services or new runtime infrastructure.

- Run the exact pinned action's config/proxy path with CLI/proxy 0.169.0. Capture method, path, fake Authorization and normalized body at a local fake gateway. Assert proxy overwrites caller Authorization, preserves the full upstream URL, forwards SSE, and denies compact/WebSocket/unknown paths.
- Script fake Responses SSE to produce a tool round trip, forced compaction, child request if enabled, 5xx, dropped stream, and missing final usage. Assert every attempted generation reaches the fake gateway. Record model/tier changes and injected output cap. Use existing upstream [client tests](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/tests/suite/client.rs) and [compaction tests](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/tests/suite/compact.rs) as fixtures; no need to re-create a model.
- Against a disposable local ledger, race two requests for the final allowance; exactly one admits. Exercise reruns sharing one update, duplicate settlement, crash after reservation/send, and unknown usage followed by retry: zero extra upstream calls. Reject forged job identity, unexpected model/tier/tool/path, redirect, malformed counter result and database outage before inference forwarding.
- Verify app analysis and clarification also traverse that fake gateway. Separately test blocked direct provider/alternate-host egress from the actual execution boundary. A loopback-only test cannot prove hosted runner isolation.
- Passing mocks establishes routing/accounting mechanics, not counter accuracy, API cap acceptance, or invoice guarantees. Resolve counting price and provider failure/retry semantics with authoritative OpenAI confirmation; any later live validation needs separate authorization. Until then, the honest deliverable is a constrained admission budget design with explicit blockers, not a proven strict monetary ceiling.

## Executed local spike — 2026-11-28

**Verdict:** real Codex CLI/proxy routing and a minimal reservation gate work together locally. A strict OpenAI invoice ceiling is still unproven. No production code, API calls to OpenAI, real credentials, deployments, or GitHub workflow runs were used.

The reproducible throwaway harness is [scripts/design-budget-spike.mjs](../scripts/design-budget-spike.mjs). It runs the installed CLI **0.169.0**, the official proxy **0.169.0**, two loopback HTTP servers, and a disposable SQLite ledger. Its custom provider matches the pinned action's `writeProxyConfig.ts`; it does **not** execute the entire GitHub Action or its runner isolation. Subagents, shell tools, and web search are disabled. A harmless `get_goal` call provides the real CLI tool round trip (it returns a persistent-thread error in ephemeral mode).

Fake input usage is 10 tokens, with fake prices of 2 units/input token and 3 units/output token. The output ceiling is 20 tokens. These are deliberately arbitrary test units, **not dollars, production prices, or measured input counts**. The fake gateway buffers SSE before forwarding; production streaming behavior is not established by this spike.

### Verified by executed assertions

- Real CLI tool follow-up traverses the real proxy and gateway; the gateway injects `max_output_tokens` and `service_tier=default`. Actual fake usage settles and releases unused funds.
- Exhausting the allowance blocks the next model request and a subsequent retry before the fake provider receives another call.
- A fake upstream 500, an interrupted stream, and missing terminal usage retain the full reservation and stop the update. The interrupted stream causes a real CLI retry, which the gateway denies without forwarding again.
- **Important:** a completed response with missing usage produces CLI exit **0**, even though the gateway stops the update. Publishing/completion must check authoritative budget status, not only Action success. Ambiguous upstream errors become terminal budget errors in the mock; these do not test provider-internal retry billing.
- Two overlapping HTTP requests competing for one reservation admit exactly one upstream request. SQLite transaction/connection-reopen checks preserve the hold; duplicate settlement does not charge twice. Remaining allowance reduces the next output ceiling. This is not yet a Supabase concurrency or full process-crash test.
- Unknown model, priority tier, hosted web-search tool, forged credential, simulated database outage, and alternate gateway paths do not forward inference.
- The real proxy rejects standalone compact, Chat Completions, unknown paths, GET inference, and an actual WebSocket upgrade. It replaces a caller-supplied Authorization header with the fake configured credential and preserves the complete update-specific upstream URL.
- A forced real CLI compaction is identified by `request_kind=compaction` in captured metadata. All three requests (initial tool call, compaction, continuation) traverse the gateway and settle against the same allowance.

### Reproduce

Requires Node with `node:sqlite` (executed with Node **26.5.1**), Codex CLI **0.169.0**, and the matching [official proxy release](https://github.com/openai/codex/releases/tag/rust-v0.169.0). Download/extract the platform's proxy into a temporary directory; do not install it globally or change application dependencies.

```sh
SPIKE_PROXY_BINARY=/absolute/path/to/codex-responses-api-proxy-aarch64-apple-darwin node scripts/design-budget-spike.mjs
```

The harness prints assertions and the path to captured fake requests and CLI results. It creates fresh temporary homes, supplies an allowlisted environment with no real API credentials, points HTTP proxies at loopback, and terminates its servers/proxies after the run. Those settings are **not a proof of runner-wide network isolation**. No real model generates or executes instructions.

Final run: all assertions passed; captured evidence was written to `/var/folders/_6/2nqz9gm10x3d9_5jh6gxw6x80000gn/T/design-budget-spike-ZPshys/results.json` (temporary, not committed). `node --check`, scoped ESLint, and `git diff --check` passed. The worktree has no installed dependencies; scoped ESLint reused the original checkout's generated configuration without its type-generation write hook. Full application tests, typecheck, and build were not run for this isolated harness/documentation change.

### Still unverified

- OpenAI token-counter accuracy/price for actual images, full Codex histories and compaction; production price and service-tier bounds; invoice behavior on failures/disconnections.
- Actual GitHub-hosted runner egress controls and proof that no alternate provider or paid MCP/tool can bypass the gateway. Subagents were deliberately disabled, not tested.
- App analysis/clarification integration, canonical update identity across independent workflow runs, real OIDC authentication, production database atomicity, complete crash recovery, counter outages, and upstream redirect handling. The spike's fake credentials and SQLite are not implementations of these controls.
- The gateway's injected cap is accepted by the mock; a paid provider request has not validated it. The CLI reports fallback model metadata locally, so this is transport/accounting evidence, not a production model catalog test.

**Next implementation prerequisite:** establish an authoritative per-request charge bound (including counting and ambiguous failures) and a credential/egress boundary. Otherwise the product can promise an admission allowance with conservative holds, but not a verified hard invoice cap.
